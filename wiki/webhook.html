Webhook

DEFINITION Ein Webhook ist eine HTTP-Anfrage, die ein System automatisch an eine andere URL sendet, sobald ein bestimmtes Ereignis eintritt — z.B. neue Bestellung, neuer Lead, geänderter Datensatz. Im Gegensatz zu klassischen APIs, bei denen man aktiv abfragen muss, bekommt man bei Webhooks Daten "gepusht" und sofort benachrichtigt.

Webhook vs. API — der zentrale Unterschied

Stell dir vor, du wartest auf ein Paket. Zwei Möglichkeiten:

  • Polling (API): Du fragst jede halbe Stunde am Schalter: "Ist mein Paket schon da?" — irgendwann ist es da. Aber: viele unnötige Fragen, oft umsonst.
  • Webhook: Du gibst deine Telefonnummer ab und bekommst angerufen, sobald das Paket da ist. Effizient, sofortig, kein Warten.

In Software übersetzt: Eine API ruft man aktiv auf. Ein Webhook ist eine URL, die ein anderes System anruft, sobald etwas passiert. Webhooks sind effizienter und schneller — kein dauerhaftes Polling, sofortige Updates.

Typische Webhook-Anwendungen

  • Stripe: Sendet Webhook bei neuer Zahlung, Refund, Chargeback, Subscription-Update
  • Shopify: Bei neuer Bestellung, Storno, Lagerbestand-Änderung
  • HubSpot / Pipedrive: Bei Lead-Status-Änderung, neuem Deal, Form-Submission
  • GitHub: Bei Code-Push, Pull-Request, Issue-Erstellung
  • Calendly: Bei neuer Terminbuchung oder Stornierung
  • Custom-Dashboards: Empfangen Webhooks von all diesen Quellen → Live-Updates in Sekunden

Häufige Fragen

Sind Webhooks sicher?

So sicher wie die Implementierung. Best Practices: HTTPS-only, Signatur-Validierung (HMAC), IP-Whitelisting wo möglich, Idempotency-Keys gegen doppelte Verarbeitung, Replay-Protection mit Timestamps.

Was passiert, wenn der Empfänger offline ist?

Gute Webhook-Sender (Stripe, Shopify) implementieren Retry-Logik mit exponentiellem Backoff — sie versuchen mehrfach. Der Empfänger sollte Idempotenz garantieren, damit Doppel-Lieferungen keine Probleme verursachen.

Wann nimmt man Webhooks statt API?

Webhooks sind ideal für Event-getriebene Workflows mit niedriger Latenz-Anforderung (z.B. "neue Bestellung → sofort an CRM und Lager melden"). APIs nimmt man, wenn man gezielt eine bestimmte Information abfragen will oder Bulk-Daten ziehen.
